0001 基于Pi的肿瘤医学论文视觉特征文本提取智能体开发计划
0002 本任务的目标是：读取用户提供的肿瘤相关医学论文，提取其中关于医学图像中肿瘤视觉特征的原文描述，保留出处与必要上下文，形成可人工核对、可导出的证据记录，为后续特征整理、需求审核和数学建模提供输入。本阶段交付的是文献证据及提取工具。
0003 首个可交互版本目前供用户本人使用，接收逐篇上传的论文PDF；支持多个独立任务并行处理，每篇分别设置范围、展示进度、审核和导出。批量提交及统一批次管理留待后续扩展。不限定癌种，以肺癌、肠癌作为起始评测对象。放射、病理、内镜论文均允许输入，先验证CT/MRI，其他模态标明尚未验证。首版支持中文和英文文本型PDF；扫描型及需要OCR的混合型PDF留待后续扩展，无法覆盖的内容明确提示，不将部分处理标为全文完成。
0004 拟实现的主要功能如下：
0005 • 提取前依次选择癌种、图像类型，界面展示对应的视觉特征集合，用户勾选特征或选择不限。首次打开时三层均为“不限”，每层可切换为限制并多选；限制模式未选任何项时提示补选或由用户主动改为不限。上游改选后保留仍适用的下游选择，标出失效项，由用户调整后开始，不静默放宽范围。提交前展示本次范围，点击开始抽取即提交，不增加默认参数逐项弹窗确认。这是联动筛选关系，各特征保留适用的癌种与图像类型；具体医学上下位关系在S2核验。
0006 • 按癌种与图像类型整理可选特征集合，记录同义表述、适用关系、来源和版本；集合可经审核扩展，不限模式不受固定词表限制，暂无集合不阻断开放抽取。
0007 • 读取论文，提取肿瘤及相关征象的图像表现和具有明确影像含义的测量描述，包括位置、大小、形态、边缘、内部结构及各图像类型适用的特征等。特征不限时，在所选癌种和图像类型范围内开放抽取、分类整理，新特征保留待审核；限制特征时，仅抽取勾选项及其同义表述，范围外内容不作为独立特征输出，必要上下文仍可保留。单纯算法流程、模型特征向量和性能指标不作为独立视觉特征证据。
0008 • 保存原文及论文身份、PDF页码或文本位置，保留模态、否定、不确定性、数值单位和适用条件（即提取肿瘤特征描述时，把影响原意的限定信息一起保留下来，避免只抽取特征名称后改变论文的意思）；原文与可选译文、归纳说明分别展示。
0009 • 边处理边展示，尽快展示首批带出处的候选结果，继续处理全文并反馈进度；全文完成后汇总核验，必要时更新候选及状态；读取失败、未处理部分及定位不可靠的记录明确标记。
0010 • 提供原文对照、候选增删改（用户可以对最终结果进行修改）、审核和导出；区分候选结果与人工审核通过的证据；候选经逐条人工核对后进入已审核导出。首版采用方案B，逐篇审核与导出，保留必要运行及审核记录；跨论文统一证据库和查询后续扩展。任务保留期间一并保留云服务器数据卷中的PDF；删除时告知清理内容，共享引用未解除的PDF继续保留；文件缺失时提示，重新上传相同文件并校验后可恢复关联。
0011 实现采用Pi TypeScript SDK作为智能体基座，由Pi组织模型交互和工具调用。当前已迁移到阿里云服务器，项目根目录为/home/ecs-user/projects/t1-agent，应用代码直接在该根目录下组织；开发及PDF解析在该服务器上开展，抽取大语言模型通过API调用；解析器和正式模型结合真实论文对照评测确定，不以本地电脑配置限制解析器选型。应用先通过联动界面接收本次抽取范围，再将论文PDF引用、范围和规则版本传给Pi处理；抽取范围选择与T2/T3的数据生成默认参数逐项确认分开。范围选择与校验、PDF解析、原文定位、结果校验、审核界面和导出使用适合的普通程序或工具接口；任务规则可按需封装为Skill（智能体进行抽取的任务）。模型、解析工具等技术配置由开发和部署侧管理；项目采用SQLite保存本次范围、特征集合版本、运行、候选及审核记录；原PDF和解析产物保存在云服务器持久化数据卷；SSE推送进度和候选更新，刷新或断线后恢复页面状态；业务权限由项目配置；短暂API错误有限重试，异常中断后由用户重新启动完整抽取并保留旧结果。断点续跑登记为后续扩展T1-F01，不计入首版验收。
0012 实际流程：
0013 上传PDF → 选择癌种 → 选择图像类型 → 展示对应特征集合并勾选或选择不限 → 解析与原文定位 → 按范围抽取、语境核验并渐进展示 → 全文汇总核验与人工审核 → 逐篇导出证据并衔接后续建模。
