# T1 论文原文工作台

从文本型PDF提取肿瘤影像外观原文，保留出处、必要语境、整幅Figure和原图注，供逐篇核对与导出。正式主流程为B0；F仅保留实验实现与历史对照。

当前阶段、重要决定、实际验证和未完成项以[统一交付记录](docs/acceptance/finalization-2026-11-09/stage-matrix.json)为入口。S4当前开发迭代已由用户接受，S5功能与界面已按用户授权由代理审核接受。S7容器、备份恢复、隔离及导出工程已有实证；最后真实部署回归因供应商响应模型标识不符停止，任务范围与全文汇总未完成，S7完整门槛仍未通过。普通模型保持未启用，全部试验余额关闭。 S2真实医学目录与完整S6独立质量/性能验收尚未通过，不作医学精度或总体召回保证。

## 访问与启动

- 现有工作台：**http://127.0.0.1:30141/**
- 宿主后端健康：**http://127.0.0.1:3210/health**
- 新Docker部署的默认入口为loopback **30142**，使用独立持久卷；[部署、模型准备、备份与恢复](deploy/README.md)包含完整步骤。

远程访问使用SSH或开发环境端口转发。复用已运行的服务，不同时启动两个Next进程或两个写同一SQLite的后端，不把现有30141数据目录直接交给验证容器。

以下命令均在`code/`执行。宿主后端使用独立公开工作台配置和私有`.env`密钥：首次建立`deploy/local/workbench.env`时参考`deploy/host.env.example`，保留已有配置与密钥。后端启动会显式载入两者：

```bash
sh deploy/start-host.sh
```

前端生产构建/启动在独立终端运行；已有服务先有序停止，再构建并启动唯一实例：

```bash
bash scripts/with-node.sh npm run build:web
bash scripts/with-node.sh npm run start:web
```

开发时可用`bash scripts/with-node.sh npm run dev:web`替代生产前端，默认仍30141。`npm run dev:server`不自动载入工作台开关/限额；不要仅改`.env`就假定这些已生效。首次依赖/CPU模型准备及Docker启动按[部署说明](deploy/README.md)执行，不运行上游通用pi-web入口或另建前端。

## 操作流程

1. 逐篇上传PDF（上限50MiB），三层范围默认不限。真实医学目录未核，未配置受信目录时限制项不可用；空选/失效不自动放宽。
2. 点击开始，查看排队、执行、任务范围处理、全文汇总和来源限制。刷新/关闭网页不取消后台；失败/中断保留成果，重新开始创建新run，不自动续跑。
3. 对照原PDF、原文、语境与整幅Figure/原图注。同源组只收拢展示，成员及其版本/归因差异保留，组数不是独立医学事实数。原字形或来源风险按实际守卫隔离，不凭语义猜单位或替作者改图注。
4. 按当前版本逐条审核，可重选来源、补录/删除、修订标签/备注；文字确认与图片确认独立，未核图片不阻断已确认文字。AI建议、开发抽样和代理工程审核不会自动批准论文记录。
5. 按篇下载候选或已审核的JSONL、CSV和证据包。已审核导出仍逐成员门控；PDF缺失/SHA不符时停止新抽取与已审核导出，可用同SHA文件恢复来源。

## 模型与限额

默认模型已选AGICTO **gpt-6-luna / medium / openai-responses**，既有供应商exact alias政策保留。这是成本方向和工程兼容性选择，不是医学最优或竞品比较结论。默认模型已选定，但当前实例仍未启用付费抽取；已有结果可查看、审核与导出，完整部署启用前置尚未满足。

普通用户仅点击开始；上传、查看、审核和导出不发模型请求，不填写实验授权表。每个新run独立最多**80请求、200万输入token、12万输出token、30分钟执行时间**；已实现2个FIFO执行槽，第三任务持久排队且可取消；重启标中断，不自动续跑。 排队等待单列，执行时间包含CPU解析、模型和全文汇总。有限重试计入本次预算，无自动循环或旧试验余额继承。请求/时间受应用硬限，token按本地预留及供应商回报计量；不承诺供应商货币账单绝对截断。

服务器管理provider、密钥、目录与限额，浏览器不能扩大配置。克隆示例保持模型关闭；当前实例的实际模型/额度/启用状态以页面及服务capabilities为准。医学目录的配置能力与目录内容是否经真实医学核验分开。

## 目录与证据

- `apps/server/`、`apps/pi-web/`：Fastify与唯一Next工作台；`packages/`为受限Agent、契约及交付核心。
- `services/pdf-parser/`：Docling CPU及原文锚点；`deploy/`：容器、模型校验、备份恢复与宿主配置。
- `runtime-data/`：SQLite、源PDF、IR、整图、版本、审核及每run账本；隔离测试库不替换生产库。
- `evaluation/`、`docs/acceptance/`：来源与冻结实证，部分文件被生产工作台直接引用，不按历史目录整体删除。
- `third_party/pi-web/`：固定上游源码、SHA及MIT来源。上游终端/任意文件/凭证和通用coding API不作为T1业务接口。
- 开发计划只在[主计划](../方案/子任务T1/T1智能体开发计划.docx)与[执行说明](../方案/子任务T1/T1开发执行说明.docx)维护，本页仅为工程使用说明。
